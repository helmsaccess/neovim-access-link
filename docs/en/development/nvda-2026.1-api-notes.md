# NVDA API boundaries

## Scope and source basis

This reference records the NVDA contracts on which the add-on currently
depends. It was checked against official source tag `release-2026.1.1`, commit
`5d92106f17e461dac62aa48257bbbf4183e033d0`. Approved version boundaries are in
[compatibility](compatibility.md); private exceptions are justified in
[ADR-0002](adr/0002-nvda-api-boundaries.md).

## Lifetime and event ownership

- `globalPluginHandler.GlobalPlugin` provides one lifetime for settings, tools,
  and shared services.
- The Windows Terminal `appModuleHandler.AppModule` owns application-specific
  events, overlay selection, configurable scripts, and every invocation of
  `nextHandler`.
- Background threads return NVDA output through
  `queueHandler.queueFunction(queueHandler.eventQueue, ...)`.
- `chooseNVDAObjectOverlayClasses()` sees NVDA's already selected native
  terminal classes in `clsList`. The add-on selects its fail-open mixin from
  those classes and revalidates service, focus, and assignment only when a
  region or routing operation is requested.

Suppression is permitted only for an authenticated, focused, exactly bound
Neovim session. A missing service, timeout, exception, focus loss, reload, or
deactivation invokes NVDA's native path.

## Input contracts

`inputCore.decide_handleRawKey` is too early for the F12 proof. The AppModule
therefore manages registration with the public
`inputCore.decide_executeGesture` decider. Registration exists only while at
least one Windows Terminal AppModule is alive and considers only F12,
explicitly supported contextual gestures, and the exactly identified public
Braille line command.

Without an NVDA script binding, F12 remains a physical terminal key press.
Claim work is queued separately and never runs on the input-hook thread. Focus
object, concrete AppModule instance, control identity, service generation, and
gate must match before every action. Every other gesture remains unchanged.

Repeated Braille routing uses NVDA's public profile-aware
`config.conf["keyboard"]["multiPressTimeout"]` setting and `core.callLater`.
The add-on reads no private gesture counters or timer internals.

## Public Braille contracts

- `braille.TextInfoRegion` participates in normal caret following. The add-on
  region derives from it but translates semantic Neovim text through public
  `Region.update()`.
- `Region.rawText`, `cursorPos`, `selectionStart`, `selectionEnd`, and
  `brailleToRawPos` provide text, cursor, selection, and routing. A virtual end
  or empty cell can be represented as ordinary text content.
- `Region.nextLine()` and `previousLine(start=False)` are the public extension
  points for NVDA's Braille line commands. The add-on overrides these methods
  and registers no display-specific gestures.
- `BrailleBuffer.windowStartPos` preserves and restores the horizontal viewport
  of a confirmed Braille exploration session. Context and length are checked
  before every restoration.
- `braille.getFocusRegions()` treats `AttributeError` and
  `NotImplementedError` as native fallback. The add-on region follows this
  contract for review tether and unconfirmed state.
- `braille.handler.message()` displays translated transient suggestions and
  selection information. The ordinary editor region is then restored through
  public focus and update paths.

## Bounded private exception

NVDA has no public operation to dismiss exactly one add-on-owned Braille
message immediately and no per-message lifetime. Only for that case, the
add-on accesses the identity-checked message buffer, its timer, and
`_dismissMessage`. ADR-0002 registers the access, tests bound it, and it must
not expand to normal editor Braille.

Any new private NVDA access requires source review, justification, a narrow
adapter, negative tests, fail-open behavior, and an updated ADR before
introduction.

## Manifest and localized interface

`minimumNVDAVersion` and `lastTestedNVDAVersion` are validated add-on API
versions; the minimum cannot exceed the last-tested version. Menu and setting
names in user documentation come from NVDA or add-on translation catalogs and
are not translated ad hoc.

Practical testing covers Windows Terminal, multiple tabs, panes, and windows,
plus the described AppModule and Braille paths with the reference version.
Other frontends and a broader NVDA/UIA matrix are not approved.
